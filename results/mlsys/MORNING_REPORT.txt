THE PREBUILT FLASH-ATTN WHEEL (your item 4)
  The file said only `pip install --no-build-isolation flash-attn`, which
  COMPILES — tens of minutes of paid GPU time per fresh pod. FlashAttention
  publishes wheels whose filename encodes four things that must all agree:

    flash_attn-2.8.3+cu12torch2.5cxx11abiFALSE-cp310-cp310-linux_x86_64.whl

  With the locked torch==2.5.1+cu124 on python 3.10 the tag is cu12 / torch2.5
  / cp310; the C++11 ABI component is not guessable, so pod_env.sh probes it
  from the interpreter (torch._C._GLIBCXX_USE_CXX11_ABI) and falls back to the
  source build only when no wheel exists at that tag.

3. WHAT THE FIRST 8x RUN EXPOSED (7625c28)
--------------------------------------------------------------------------------
At 02:21Z the watcher launched f7cb8d2f9cf8484f84f400b63f3f45ca in us-midwest-1,
staged everything, started the manifest, and gate_calibration died after 2
seconds with `No module named 'transformers'`. It then billed for another two
hours, because the completion check could not fire either. Four causes:

  A COMPLETION CHECK THAT COULD NEVER FIRE
    `ssh host 'pgrep -f mlsys_manifest.sh'` matches the remote shell running
    it, so it returned 0 with no manifest running. There was no reachable
    "finished" state. The manifest now runs behind a wrapper that records its
    exit code in ~/manifest.rc; the watcher reads that file, only after an ssh
    that exited 0, and only a numeric value counts.

  AN ENVIRONMENT THAT WAS ASSUMED, NOT BUILT
    The image had no conda anywhere and the resolution ended in
    `else command -v python3`. pod_env.sh now builds the environment (installing
    Miniconda if absent) from the recipe in auto_execute_phase_c.sh, and the
    resolution fails closed.

  THE ENV NAME WAS WRONG IN EVERY LOOKUP
    The bootstrap creates `rasd-gpu`; the watcher looked for `rasd`, which is
    this Mac's name. A correctly provisioned pod would have been missed.

  A GATED-MODEL TOKEN NEVER FORWARDED
    Every target model is gated (meta-llama/Llama-2-7b-hf and
    meta-llama/Llama-3.1-8B both return 200 only with a token). The watcher now
    refuses to launch without it, forwards it, and never logs it.

FAIL FAST AND THE STALL WATCHDOGS
  manifest.rc != 0 -> logs to results/mlsys/incident_<UTC>/ then
  terminate_and_confirm and exit 7, BEFORE the normal verify-and-merge path.
  A stall, or a manifest process gone with no marker, does the same. Default
  20 minutes, with per-stage overrides in configs/mlsys_stall_thresholds.json
  for stages whose single runs are long; every override carries its
  justification, and BOTH watchdogs read that one file. The pod enforces the
  same rule itself, independently of this machine.
